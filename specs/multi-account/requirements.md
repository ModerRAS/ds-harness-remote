# 需求文档

## 介绍

官方自建 Server 只有 `DSH_SERVER_ACCOUNT` 这一个账号。任何能登录的人都看得到全部 Host，也能向它们发起连接。本改动让同一进程服务多个账号，账号之间的设备、凭据、网页会话和中继互不可见。官方插件不用改，仍然用账号密码登录。

## 需求

### 需求 1 - 多账号登录

**用户故事：** 作为自建 Server 的使用者，我希望用自己的账号登录，而不是和所有人共用一套密码。

#### 验收标准

1. When 进程启动时，系统应当用 `DSH_SERVER_ACCOUNT` 与 `DSH_SERVER_PASSWORD` 创建或更新种子账号。
2. When 注册码未配置时，系统应当拒绝 `POST /api/v1/auth/register`。
3. When 配置了至少 12 字符的 `DSH_SERVER_REGISTRATION_CODE` 且注册码正确时，系统应当创建新账号并建立该账号的登录会话。
4. When 账号名仅大小写不同时，系统应当视为同一个账号。
5. When 密码错误或账号不存在时，系统应当返回相同的认证失败，且不说明账号是否存在。

### 需求 2 - 账号隔离

**用户故事：** 作为某个账号的用户，我不希望别人看见我的 Host，或连进我的电脑。

#### 验收标准

1. When 用户查看设备、在线状态或修改设备名时，系统应当只处理该用户自己的设备；其他账号的设备标识返回不存在。
2. When 客户端请求连接一台 Host 时，系统应当只在同一账号内查找；找不到时按 Host 不在线处理，且不向其他账号的 Host 发送连接请求。
3. When 两个账号登记了相同的设备标识时，系统应当让两边同时在线，任一方断开或顶替连接都不得影响另一方。
4. When 签发网页会话、设备令牌、TURN 凭据或中继链路时，系统应当把它们绑定到一个账号，别的账号不能拿来使用。
5. When 修改种子账号密码时，系统应当只使该账号的设备令牌失效。
6. While 一个账号已经用满自己的设备、令牌、在线连接或中继额度，when 另一个账号仍在自己的额度内，系统应当继续接受后者的注册和连接。

### 需求 3 - 旧数据可升级

**用户故事：** 作为已经在用单账号 Server 的人，我希望升级后原来的设备还在。

#### 验收标准

1. When 读到 version 1 的 `state.json` 时，系统应当把它升级为该账号的数据并保留设备。
2. When 种子账号名与文件里已有账号不同时，系统应当保留原账号，并另外确保种子账号存在。
