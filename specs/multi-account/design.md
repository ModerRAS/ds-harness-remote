# 技术方案

## 架构

仍是单进程 `apps/server`。持久化从 version 1 的单个 `account/devices/tokens` 改为 version 2：`accounts[账号键]` 保存显示名、口令校验值和设备，令牌表增加 `accountKey`。账号键是去掉首尾空白后的小写登录名。

网页会话从「令牌 → 过期时间」改为「令牌 → 账号 + 过期时间」。WebSocket 在线表和中继链路的键是 `账号 + 设备标识`，线上协议仍只出现设备标识。

## 技术选型

- 沿用现有 HTTP、WebSocket、scrypt 口令校验和 JSON 文件，不引入数据库。
- 不改插件协议。登录仍是 `POST /api/v1/auth/login`。
- 注册是新增的 `GET /api/v1/auth/registration` 与 `POST /api/v1/auth/register`。登录页在注册开启时显示注册表单。

## 隔离边界

设备列表、改名、在线查询、注册、刷新、连接请求、信令、中继和 TURN 授权都先确定调用方账号，再只访问该账号的数据。跨账号设备查询返回 404。跨账号连接返回 Host 不在线，不产生链路。

每个账号沿用原来的额度：256 台设备、16384 个令牌、256 条在线连接、256 条中继、64 个网页会话。进程级上限提高到 4096 条连接/链路/会话、128 个账号，避免一个账号占满原来的全局 256 个名额。

## 升级

version 1 文件在启动时转成该账号的 version 2 记录。种子账号每次启动按环境变量核对口令；口令变化只删除该账号的令牌。种子账号改名不再清空其他账号。

## 测试

`pnpm --filter @dsh-remote/server test` 覆盖双账号设备列表、同设备标识并存、跨账号连接不送达、注册开关、旧状态升级，以及种子密码变更不影响其他账号。

## 不包含

OAuth、管理员查看他人设备、完整 Remote Web 会话界面、插件改动。
